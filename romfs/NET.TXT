NETWORKING ON SNOS

This machine has no network hardware. What it has is a serial link to a
gateway, and the gateway does everything the SNES cannot.

WHY A GATEWAY

Almost everything on the internet now speaks TLS, and a TLS handshake needs
elliptic-curve arithmetic. On a 3.58 MHz 65816 that runs to minutes per
connection, before a single byte of your page arrives. Gzip and chunked
transfer encoding are the same kind of work: easy on the far side, and the
wrong thing to spend this CPU on.

So the gateway terminates TLS, resolves names, follows redirects, and hands
back plain bytes. It is a forward proxy, not a man in the middle: it makes
ordinary honest connections as itself, so nothing forges a certificate and
there is no authority to install here.

WHAT THE SNES ACTUALLY DOES

It sees a stream. Nothing more. Commands differ only in how a stream gets
opened, so the gateway can learn new protocols without this side changing at
all.

The link exchanges one fixed-size frame per video frame, in both directions
at once, and the SNES supplies the clock. The gateway cannot push; it answers.
Every frame carries a checksum and a sequence number, because terminating TCP
at the gateway leaves this cable as the only unprotected hop, and it is
carrying the whole payload.

COMMANDS

  net                    is a gateway attached?
  get URL DEST           fetch a URL; a DEST of - prints it
  httpd [PORT]           serve this volume to the network
  netecho [PORT]         a TCP echo server
  irc HOST [NICK] [#CH]  talk on IRC

A fetch can be interrupted with any key. Progress is shown as it arrives,
because at this speed a large file takes long enough that a still screen and
a wedged machine look identical.

SPEED

Roughly 1.7 KB/s at present. That is fine for text and poor for anything
else, which is a reasonable description of what this machine is for.
